## 1. 哪些代码与结果检查通过

### 数据对齐

- 发布包 `predictions.pkl` 与 `test_data.pkl` 的 3,874 个蛋白顺序相同，蛋白 ID 唯一。
- 5,862 个预测术语唯一，标签恰好等于发布包传播注释在这些术语上的成员关系，没有发现标签列错位。
- 派生 cc/mf/bp NPZ 的词表与理论 ID 对齐，标签与原文件对应列完全相同；分数与原预测经 1e-6 截断后的差仅约 2.5e-15。
- cc/mf 标签不违反当前 is-a 约束。bp 存在额外映射问题，见后文。

### 推理与指标

- 对 cc/mf 全部选中蛋白重算 raw、max-closure、exact WMC，原记录的 Fmax、所称 AUPR、Brier、ECE 均精确复现。
- 每个命名空间抽查三个“蛋白—术语”，包括被大幅压低的真实标签，用独立稠密变量消元检查。电路边缘与独立结果最大差约 7.8e-16，log Z 最大差约 3.6e-15。
- 小词表 min-fill 宽度仅 cc=4、mf=7，因此精确编译很便宜在结构上完全可信。
- `max_closure` 的叶到根传播正确。
- Fmax 的蛋白平均 precision/recall 计算正确；Brier 和 15 等宽分箱的 pooled ECE 也按所述定义实现。
- bootstrap 对所有方法使用同一批蛋白索引，每次重新优化 Fmax，正确计算配对指标差。它估计的是固定模型和当前样本分布下的重采样不确定性，不包括模型训练、序列家族相关性及其他预测器的不确定性。

因此，没有发现“算错 WMC 导致预测下降”的证据。这里并非只相信同一实现的重复运行，另有独立推理参照。

## 2. 评测口径的具体问题

### 2.1 原实验使用 CNN 分支，不是完整 DeepGOPlus

`predictions.pkl` 中的 `preds` 来自 CNN。官方 `evaluate_deepgoplus.py` 还将它与 DIAMOND 同源转移分数融合；发布包中 mf/bp/cc 的同源权重分别为 0.67/0.64/0.52。

因此原实验应称“DeepGOPlus 发布包的 CNN 分支”，不能直接作为完整标准混合模型的官方复现。当前分支本身仍是有价值的真实神经预测器。

来源：[官方评测代码](https://raw.githubusercontent.com/bio-ontology-research-group/deepgoplus/master/evaluate_deepgoplus.py)、[官方训练与预测代码](https://raw.githubusercontent.com/bio-ontology-research-group/deepgoplus/master/deepgoplus.py)，以及本地 `metadata/last_release.json`。

### 2.2 根术语被计入，AUPR 定义不同

当前脚本将 `GO:0005575` 和 `GO:0003674` 计入评价。官方脚本会剔除命名空间根节点，且对预测集合做祖先传播。原 cc 的 2,912 个有标签蛋白中有三个仅剩根标签；去根后正标签样本为 2,909。mf 仍为 2,129。

当前 `aupr` 是将所有“蛋白—术语”对展开后的顺序式 average precision，不是官方脚本对蛋白平均 precision/recall 曲线的梯形面积。作为额外的 micro AP 指标可以使用，但要正确命名，不能直接与发布包 AUPR 比较。

还有一个实现细节：相同分数被顺序拆开，AP 会依赖行顺序。应在每组并列分数的末尾计算 precision。实测修正幅度很小，最大约 1.9e-5，不足以改变此次主要结论，但对于约 1e-3 的小差异应使用规范实现。

当采用阈值后自动向祖先传播的协议时，在同一 is-a 词表上，raw 与 max-closure 的预测集合逐阈值相同。这不是矛盾，而是“闭包在评分前还是阈值后做”的等价性。因此 raw 与 max-closure 分开的当前表格是一种自定义后处理比较，并非原样的官方 CAFA/DeepGOPlus 协议。

### 2.3 词表与标签还有清洗工作

5,862 项原词表中有 26 项被严格 ID 匹配排除。其中包括 alt_id：例如 `GO:0000778` 实际是 `GO:0000776` 的别名；`GO:0001085`、`GO:0001102`、`GO:0001103` 均映射到 `GO:0061629`。另有废弃项。cc/mf/bp 分别保留 632/730/4,474 项。

使用筛选后的共同词表做内部比较是有效的，但应披露排除规则。正式复现应处理别名与废弃项，并预先定义多个原预测头映射到同一现行术语时的合并规则，避免把重复的别名分数当作独立证据。

bp 标签在当前理论下有 32 个“孩子标签为 1、父标签为 0”的对，涉及 25 个蛋白和五条边。未来做 bp 下游实验前必须处理版本/注释闭包的一致性。该问题不影响此次 cc/mf 的负面结果，也不影响 bp 分数上的纯推理误差比较。

逻辑投影算法本身对纯蕴含链是正确的：它保留词表节点经非词表中间点到达的下一词表祖先。但它是约束的存在投影，不能宣称保持了某个带未知词表外权重的完整 WMC 后验。此次研究任务实际是预测词表上的模型。

### 2.4 测试集的独立程度

直接读取发布包的训练集，73,592 个训练蛋白与 3,874 个测试蛋白没有相同 protein ID，符合发布包的留出划分。但两者存在 76 个相同序列字符串的交集。

这不使同一测试集上的配对比较失效，也不能仅凭这一点指控原作者评测违规。它意味着没有验证低同源或按序列簇划分的泛化；“完全没有泄漏”应改为明确描述 ID 级留出及重复序列情况。

## 3. 修订口径之后，负面结果是否仍然存在

存在，而且差距更明显。以下均在当前保留词表内，剔除根术语，并只评价去根后仍有正标签的蛋白。这里的“融合”使用发布包实际 DIAMOND 命中、训练注释和官方融合权重；不是官方完整标签空间及全部关系的基准复现。

| 输入与命名空间 | raw Fmax | max-closure Fmax | exact WMC Fmax | WMC−raw |
|---|---:|---:|---:|---:|
| CNN，cc，2,909 蛋白 | 0.65899 | 0.66155 | 0.64393 | −0.01506 |
| CNN，mf，2,129 蛋白 | 0.49495 | 0.50050 | 0.45913 | −0.03582 |
| CNN+DIAMOND，cc | 0.69857 | 0.70001 | 0.67617 | −0.02239 |
| CNN+DIAMOND，mf | 0.68130 | 0.68200 | 0.62521 | −0.05609 |

CNN 去根后重新做 1,000 次配对 bootstrap，WMC−raw 的 Fmax 95% 区间为：

- cc：[−0.01726, −0.01227]；
- mf：[−0.04151, −0.03038]。

为了排除“WMC 最优阈值被 0.01 网格漏掉”的可能，又扫描全部不同预测分数。CNN cc 的 raw/max/WMC Fmax 为 0.65923/0.66199/0.64444；mf 为 0.49531/0.50098/0.45979。融合输入上的相应值为 cc 0.69893/0.70038/0.67647、mf 0.68172/0.68257/0.62587。方向不变。

micro AP、Brier、ECE 上 WMC 的负面方向同样保留。不过“max-closure 最好”只应限定于所比较方法与指标：融合 cc 的 micro AP 是 raw 略高于 max-closure。更不能据此宣称 max-closure 胜过尚未测试的保序回归等方法。

本次补充的融合结果没有另算完整 bootstrap 区间，因此只报告点估计方向，不将其写作新增统计显著性结论。

## 4. 哪些结论同意，哪些解释超出了证据

### 同意的部分

1. 当前这类乘积条件化并没有在此次真实预测器上改善标签预测，反而明显变差。论文不能再把“满足约束”直接写成“改善预测”。
2. cc/mf 的推理已经足够便宜，新模块方法不能以这两个词表上的可计算性作为独有能力。
3. 精确 WMC 与 BP 的下游 Fmax 差距远小于 WMC 与原分数的差距。原口径下精确−BP 分别为 cc 0.000312、mf 0.000861；“约 0.0005”只是概括，不能代替具体数值。
4. DiamondScore 的剪枝结果不能独自承担新方法贡献。补做确定性消元基线并据此收缩贡献，是正确做法。

### 需要收窄的部分

**“原因已证明是证据重复计算”过强。** 这是合理的模型失配解释，而非已由这些计数唯一识别的因果机制。mf 的确有 3,209 个真实标签下降超过 0.1、870 个未注释项上升超过 0.1，但真实标签平均分数反而上升约 0.013。它证明存在有害的尾部改动，不能单独证明所有深层分数被系统性压低。校准、类别先验、根节点处理及本体表示也可能有作用。

数学上，可以确认更基础的事实：**已经正确的标签边缘概率，通常不是条件乘积模型的正确字面量参数。** 单边 (C\Rightarrow A) 即可证明，无需神经网络或汇合路径：

- 真实边缘为 P(A)=0.6、P(C)=0.3；合法联合为 P(00)=0.4、P(10)=0.3、P(11)=0.3。
- 将 0.6、0.3 直接作为独立权重再条件化，得到 P(A)=0.681818、P(C)=0.204545。

因此，边缘可以完全正确、完全满足层级，乘积条件化仍然会改变它们。这说明目标语义与边缘预测用途之间可能失配；不等于条件化本身在数学上有错。

**“更准、更快地算这个后验失去应用价值”过强。** 此次证据否定的是这个具体蛋白后处理用途的普遍收益。若另一个应用真正定义了独立基准分布与完整性证据，条件后验仍可有意义。概率数据库 conditioning 确有已有研究，但还要找到任务匹配的数据与强基线，而不是仅替换论文中的应用名词。[Koch 与 Olteanu 2008](https://arxiv.org/abs/0803.2212)

**不能用 0.554 与 0.689 判断原稿预测器强弱及解释旧提升。** 原稿是完整 GO cc 的另一套数据与评价，当前只有筛选词表，且根处理、标签空间不同。原稿 WMC 相对 max-closure 还有约 0.0326 Fmax 的报告差距，不能凭新实验认定它不存在。旧结果目前不可溯源，应该删除或重新实验，而不是为它指定一个未经验证的原因。

## 5. “朴素条件概率修复”的失败不是什么证据

未找到该尝试的独立脚本、配置和原始结果，只在 `RESULTS.md` 看见描述，无法验证 0.06–0.13 的具体数值。根据描述，把 p_child/p_parent 直接当新独立权重再做 WMC，本来就不等价于局部条件概率模型；它失败不能用于否定正确的条件模型。

而“只有字面量权重就表达不了父关子必关、父开子以 q 开”的说法需要区分情形。

对于树，它可以通过重新参数化写成同一合法支持上的一元加权模型。设根参数为 q_root，其他节点 q_i=P(Y_i=1|Y_parent=1)，则可取一元几率

\[
\lambda_i=\frac{q_i}{1-q_i}\prod_{j\in Children(i)}(1-q_j),
\qquad p_i'=\frac{\lambda_i}{1+\lambda_i}.
\]

这是把每条边的因子在合法状态上重写、再把依赖父值的项归并到父节点，而非只替换孩子参数。

在前述两变量例中 q_C=0.5。朴素替换为一元 p_A=0.6、p_C=0.5，会得到边缘 0.75、0.375；正确一元参数 p_A'=3/7、p_C'=0.5，则准确恢复 0.6、0.3。已经用三种合法赋值直接枚举验证。

对于多父 DAG，一般需要父集合因子或辅助变量；但 BN 到 WMC 的编码是成熟技术，不能把“需要另一种编码”直接当作新的研究贡献。[Chavira 与 Darwiche 2008](https://escholarship.org/uc/item/7916m4fn)

更关键的是，多父情况下仅知道各节点边缘，不足以确定 P(所有父节点同时为真)。因此 p_child/p_parent 之类比值本身不能唯一确定一个“正确”的局部条件模型。

## 6. 对方向 B 有一个决定性的数学修正

只含 (Y_c\Rightarrow Y_p) 时，合法分布的边缘向量集合恰好是

\[
0\le\mu_i\le1,\qquad \mu_c\le\mu_p.
\]

必要性显然。充分性有直接构造：令 U 在 [0,1] 上均匀分布，设 (Y_i=1[U\le\mu_i])。所有蕴含始终成立，且每个术语的边缘恰为 μ_i。这与经典 order polytope 的顶点刻画一致。[Stanley 1986](https://math.mit.edu/~rstan/pubs/pubfiles/66.pdf)

所以，如果研究目标只是“输出最接近原预测的、能够由某个合法联合分布实现的边缘”，可以直接在这些序约束上做保序/凸投影。**不必先建立指数大小的联合分布，再反复用 WMC 求回这些边缘。**

若另加“选最大熵联合分布，并回答联合查询或处理额外证据”的要求，WMC 才可能成为有意义的计算内核。但边缘一致性本身并未指定这个联合，也不能从 Fmax 下游实验推出必须付出这项成本。上面的共同 U 构造只用于证明边缘可实现性，不代表它就是合适的生物学联合模型。

此外，Obozinski 等人的 *Consistent probabilistic outputs for protein function prediction*（Genome Biology，2008）已比较启发式、贝叶斯网络、KL 投影与保序回归，并报告不少协调方法损害预测、保序回归通常较稳健。当前提议与其问题设置有直接重叠。这不是对新方案的最终否定，但应先界定相对已有协调与投影方法的新问题和能力。[原论文](https://link.springer.com/article/10.1186/gb-2008-9-s1-s6)

因此，不认可“因为要换语义，扩展 WMC 就自动重新必要”“方向 B 天然最像 AIJ”的论证。可以做有限预算的可行性检查，但应先加入保序回归等真正相关的基线。

## 7. GO bp 与其他实现需要保留的限定

### Gibbs 是统计参照，不是可证误差界

P1.4b 的 200 个样本唯一，54 个样本的 `excess>0.01`，比例确为 27%。但代码中的 `4*chain_se + bracket_gap` 是经验不确定度，不是已证明的同时置信界。

当前各链用独立随机数，从全 0/全 1 启动，并非共享随机数的路径耦合或 CFTP。上下起点在分布意义上的单调性与样本均值严格夹住真值不同。独立链终点均值的标准误可作诊断，但跨数千术语取最大值后还要处理多重比较与共同偏差。

因此，可以写“相对该统计参照，27% 的样本显示 >0.01 的超额差异”，不能把它等同于 cc/mf 上 exact reference 或上一轮解析证书意义下的误差下界。应在可精确求解实例上先校验同一统计流程的覆盖率。

### 编译是否成功不是研究生死的二元判据

核对时 GO bp 词表编译仍运行，约 20 小时 14 分；P1.1 四个完整本体任务约 28 小时 39 分，也仍运行。不能预写最终失败。

即使成功，还需看电路大小、解析内存、每输入求值成本、多少输入才能摊销预编译、以及本体更新频率。即使失败，也只证明这份求解器、版本、配置与预算失败。一个 d4 的结果不能替代全部方法对照。

### 一个可修复的临时文件风险

`p1_2b_baseline_d4_full_theory_with_zero_units.py` 的交叉验证将工作目录设为 `Path(td)/".."`，实际会使用 `/tmp/core.cnf`、`/tmp/core.nnf`。多个同节点任务可能互相覆盖。改用任务自己的临时目录即可，`full.cnf` 与 `core.cnf` 文件名不同，无需跳到父目录。

未发现已经因该风险产生错误结果的证据；它值得修复，但不推翻此次独立验证的 P4.0 结论。

## 8. 对下一步的建议

1. **先规范化已有实验。** 明确 CNN 与融合分数；根节点、别名、废弃项、关系类型和评价词表使用统一规则；规范命名 micro AP；保存后处理分数和完整依赖哈希。cc/mf 的负面方向已有充分证据，不必继续堆同类重复实验。
2. **把机制解释与事实分开。** 如需写“为何下降”，采用已定义的小例、可控链或树、根节点设定、校准及深度分层实验，不用少量计数代替因果论证。
3. **先核查近邻再做方向 B。** 把保序回归、已有 KL 协调方法作为实质对手；明确需要的是边缘修正、联合查询、证据条件化，还是训练。若目标仅是边缘与标签预测，没有理由强行要求 WMC。
4. **方向 A 仍可研究，但需要真实任务。** 保留条件乘积模型作为明确计算对象，找到语义确实需要它的应用，比较专用构造与强精确/保证式近似方法的总成本。
5. **不要让单个编译作业决定选题。** 它提供重要实证，不能替代算法差异、成本和使用场景的判断。
6. **C 与 D 都不是自动退路。** 训练期方案需要新的技术价值；单个预测器的两个命名空间负面结果也不能直接保证某个期刊会接受。KEL1 对旧稿叙事混杂的批评，不是禁止一切训练或 NeSy 研究。

我的选择是：**接受此次负面结果，撤回普遍改善预测的应用叙事；先修订评测并完成近邻与目标界定，再决定是否投入 B。可以做短期探索，但不应预先把它当作一条已经具备 AIJ 创新性的主线。**
